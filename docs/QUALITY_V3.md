## 1. 统一“模型类别”“业务等级”“流程状态”

| 层级 | 本版含义 |
|---|---|
| YOLO 类别 | 表面擦伤、虫害损伤。不是 A/B/C 分类器，也不是优果/坏果分类器 |
| AI 筛查建议 | low→参考 B；moderate→参考 C；high→专项复核；未检出→等级待定。仅为实验性外观规则 |
| 人工业务等级 | A / B / C / REJECT；所有新复核和 B 接入使用同一词表 |
| 待复核 | 独立流程状态，不是 D 级，不默认为 A |

A=优选外观（人工核对所检图像，未确认可见目标缺陷）；B=一般外观（轻微外观缺陷，经分选评估）；C=用途待评估（负责人专项确认，不自动提供工艺）；REJECT=人工明确拒收（暂停流转与登记处置）。这些是 Demo 业务档位，不是已核定的国家、行业或采购标准。

旧记录中的原始 D 不重写、不静默改为 REJECT。新 AI 不再自动给 D 或 REJECT；新人工复核选择 A/B/C/REJECT。不存在“零个框→优果”规则。

模型漏检时新增“人工发现缺陷（模型未覆盖或漏检）”结论，可填写部位、现象和依据并保存人工等级；与模型候选分开，原图和原始预测不改写，也不补画假 AI 框。尚不确定时保持需复查和等级未定。

## 2. 实际修改了推理，而非只有界面

新增 `detail_runtime.py`：原整图推理 + 960 整图推理；较大输入（最长边至少1280、最短边至少256）再做最多四个重叠局部区域的960推理。每个框映射回方向校正原图，再按类别去重。最多六次前向、最终最多300框。

全部分支保留 manifest 置信度，不使用“没框就不断降低阈值”的逻辑。坐标、结果维度、类别、非有限数值异常时拒绝生成结果。运行配置写入本次记录，不修改模型身份或历史图片。

这种补检可能改善小缺陷检出，也可能增加误报和耗时，必须由实际回归验证。本次没有新增腐烂、霉变等类别；原两类标签覆盖不到的问题，不能靠更高分辨率凭空学会。默认 `baseline` 委托原引擎运行，便于回归与恢复。

## 3. 不再仅靠页面跳转判断“已连通”

新增 `/batches/{id}/quality-flow`，在服务端核对：

```text
最新已保存质检 ID + 人工复核版本 + 业务等级
  → 明确批准作为本次原料输入
  → B 实际建议 + 保存的 grade_source
  → 人工采用值
  → 同一 batch_id 的冷链读数、持续异常和处置
  → 综合报告 + 明确批准发布的溯源摘要
```

新的质检或复核版本使旧工艺来源过期；后端拒绝继续采用旧来源。B 返回 manual_review 或 blocked 时不能通过填写任意参数绕过。已关联的工艺采用还会检查未处置告警与仍在持续的异常；“已人工处置”不等于“温度观测恢复”。

独立手工填写的加工记录仍可保存，但明确不计入视觉来源关联。冷链是同批次实际观测/模拟记录，不由照片生成，也不是由工艺采用值生成；不声称设备已经执行。最新单张图像复核只有经过明确人工批准才作为原料业务输入，不自动升级为整批质量证明。

共用流程面板接入质检、加工、冷链和报告。冷链新增温湿度曲线，模拟/传感器来源分开展示；仅绘制已保存数据，缺测断线。

公开摘要需人工批准，等级默认不公开；原图、置信度、内部备注、操作员等不随摘要公开。摘要绑定来源指纹，来源更新后标注“摘要已过期”。旧公开事件保留，不因本次取消勾选而撤回历史公开内容。

管理端目前仍没有登录授权，仅限可信本机环境。不要将这版直接暴露公网。
