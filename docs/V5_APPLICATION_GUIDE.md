# V5.1 应用使用与升级

V5.1 的主流程是：登记批次 → 上传照片得到 AI 初评 → 加工建议与实际作业 → 冷链观测及异常处置 → 内部报告、预览并发布扫码摘要。
人工检查与修正是可选操作，不再是生成初评和加工建议的前提。

## 已有 V4 / V5 环境升级

你已经使用的数据库 `smart_fresh_c_review` 和外部图片存储目录继续保留。V5.1 沿用现有 Q4 表，本次没有新增数据库迁移，也没有重新初始化数据。旧 V5 的 AI 初评会按新规则追加有效版本；历史人工 D 不静默变成拒收，需要选择 A/B/C/REJECT 修正。

1. 将整包解压。运行根目录 `UPGRADE_V5.cmd`，目标默认是 `D:\ZhiJianData\ZhiJian-repro-test`；可以输入实际仓库路径。
2. 升级工具先校验所有待替换文件。匹配的 V4 基线或上一包 V5 文件才会覆盖；有本地修改就停止并列出冲突，不自动 reset。覆盖前备份到目标目录 `v5-upgrade-backups`。
3. 关闭旧 Java、Vue 的运行窗口；8001/8002 已运行且版本匹配时，启动器可以复用。不会自动杀掉已有进程。
4. 在目标仓库 `frontend` 执行一次 `npm ci --include=dev`。然后双击目标仓库的 `START_APP.cmd`。
5. 在本机控制台输入已有 MySQL 用户和密码，密码隐藏输入、不写配置文件、不作为命令参数。打开 `http://127.0.0.1:5173`。

如果升级校验发现不同基线，请在解压出的完整源码目录运行 V5.1。该目录同样连接已有 `smart_fresh_c_review`，无需复制或删除数据库。
完整源码不包含 `.venv` 或 `node_modules`；可在 CMD 设置 `AI_PYTHON`、`B_PYTHON` 指向已有环境的 `python.exe`。AI 入口也尝试原 `D:\ZhiJianData\envs\ai-cpu\Scripts\python.exe`。

V4 状态接口已经显示 `batch_workbench_ready=true` 时，不用再次迁移。若是在全新机器建库，应先按原交接步骤完成基础/A3/C/Q4 表，不能对已有数据库执行清空式初始化。

## 每次使用

- 在“批次管理”登记或打开批次，选择“AI 质检”。上传后点击“检测并生成等级”，结果图、本图等级和本轮等级同时可见。
- 点击“继续加工品控”。等级自动带入；A/B 的加工建议根据实际录入的温湿度计算。建议可以先生成，实际分选完成后登记，再检查采用值，实际加工后另记执行结果。
- C 进入用途评估，REJECT 初评暂停正常流转；在同页登记实际评估、隔离或退货等处置。REJECT 标明是 AI 初评或人工修正，等级记录不代替实际拒收处置。
- 冷链页导入原始 CSV，模拟与传感器来源分别标识。持续超温、未处置告警、观测断点会形成待办并限制新的工艺采用。温度恢复与人工处置是两件事。
- “报告与溯源”读取同批次来源。选择是否公开等级和用途，预览实际内容后发布。二维码打开发布快照；源记录变化后显示待更新。

所有作业和处置必须按真实发生情况填写。生成建议、采用参数、执行作业分别记录，页面不会把其中一个自动当作其他步骤已完成。

## 等级口径

当前 YOLO **检测类别**只有“表面擦伤”和“虫害损伤”。它输出缺陷框，A/B/C/REJECT 是这些检测结果之上的外观初评规则。

| 初评 | 规则输入 | 默认处理方向 |
|---|---|---|
| A | 本图没有检出当前模型覆盖的目标缺陷 | 优选商品分选 |
| B | 缺陷负担为 low | 普通商品分选 |
| C | 缺陷负担为 moderate | 分选与加工适用性评估 |
| REJECT | 缺陷负担为 high，属于拒收初评，可后续修正 | 暂停正常流转，记录实际处置 |

负担规则沿用现有 `a11-dev-burden-v1`：候选框并集 / 整图小于 0.006 为 low，0.006 至小于 0.03 为 moderate，其余为 high；候选数至少 4、较大擦伤框或较大虫害框会提升一档。重叠框按并集计算。这是整图范围规则，不是果实真实损伤面积，也不是国家/行业分级标准。

本轮等级采用本轮有效图像等级中最严重的一档，同图像去重统计；不会把多角度照片张数当成果实数量。图像人工修正优先。没有照片不会产生 A；没有框的有效检测会生成明确标为 AI 初评的 A。

当前模型尚不能覆盖腐烂、所有碰伤等其他缺陷，不能因 A 初评推断这些问题不存在。此版本没有声称四等级分类器已训练完成或准确率已提高。

## 修正与版本联动

“检查与修正”可以直接调整本轮等级、处理方向并填写原因、检查人。图像级检查在检测页折叠入口中，可确认误检、重复框、漏检等。模型原始输出始终保留。V5.1 不使用 D 作为业务等级；旧 AI 规则的 `suggested_grade=D` 仅作为历史原始字段保留，当前业务读取 `initial_assessment`。

修正、新增照片、复核或抽检范围变化会更新来源版本。当前有效人工批次修正不会被普通刷新覆盖；新增证据会重新生成本轮初评，并保留旧人工结论为历史。旧工艺建议、采用值和公开摘要不会继续被标为当前来源，须据新来源重新生成或发布。历史作业不会删除。

## 模型与服务

默认模型为 `ai-service/models/accepted/best.pt`：

- 版本：`ssda-yolov8n-20261001-8c45a0602dad-n050-sem1`
- SHA256：`8c45a0602dadf8b9f48b609e29d6d3b5e5868db5f68682da8b32583e104827a4`
- 默认 conf=0.25，IoU=0.5，imgsz=640，baseline 推理。

`run-cpu-local.cmd` 已改为默认 accepted 模型。历史 A15 资产保留作开发记录，默认启动器不将它作为回退模型。
既有诊断是训练集前 100 张对照，不是独立验证集评测；不能从其 F1 推导新应用的等级准确率。

| 服务 | 端口 | 入口 |
|---|---|---|
| YOLO | 8001 | `python scripts/app_local.py ai` |
| 加工、冷链规则 | 8002 | `python scripts/app_local.py business` |
| Java / MySQL 适配 | 8080 | `python scripts/app_local.py backend` |
| Vue | 5173 | `python scripts/app_local.py web` |

四个入口保留供排查；正常使用可直接 `python scripts/app_local.py start`。检查：`python scripts/app_local.py status`。
网页 `/api` 是 Vite 代理前缀，Java 直接访问地址是 `http://127.0.0.1:8080/workspace/status`，不要给 Java 地址加 `/api`。
应用版本应为 `ai-first-application-v5.1-20261014`。

## 手机扫码

在报告页二维码区域填写手机能访问的前端地址，如 `http://电脑局域网IP:5173`。Vue 用 `npm run dev:lan` 启动；手机和电脑须在同一可信网络。
二维码只指向公开溯源页，不公开原图、内部备注、操作人或模型分数。
本版本没有账号权限控制，适用于可信本机或可信局域网的项目使用；公开互联网部署前需要单独完成身份与权限控制。

## 验证范围

本次运行了真实 accepted 权重、真实 B 0.5.0、Java 和 Vue 的完整 HTTP 与浏览器流程。数据库为隔离 H2 MySQL 模式测试库；观测是模拟数据，实际作业字段写入明确标记的验收夹具。它证明集成流程，不是现场生产、真实传感器接入或独立缺陷/等级准确率评测。

`python scripts/verify_application_v5.py` 默认只读检查服务。写入验收需要显式指定名称含 test/acceptance 的隔离数据库、提供图片并添加 `--allow-fixture-writes`，不能对当前业务库直接写测试作业。
