# V5.1 等级契约修正 · 2026-10-14

应用版本：`ai-first-application-v5.1-20261014`。GitHub 基线：`bfccdfefde5920dd4474fb84a08d9fa78a0da72e`。

## 修正原因与行为

GitHub 集成分支和 B 加工服务的业务等级是 **A/B/C/REJECT**。上一包 V5 将旧检测建议字段中的 D 带入业务等级，改变了现有接口契约。本版恢复原契约，保留上传即产生 AI 初评、人工可后续检查修正的流程。

| 业务等级 | 当前外观初评输入 | 页面与业务行为 |
|---|---|---|
| A | 未检出当前目标缺陷 | 优选外观，进入商品分选 |
| B | low 缺陷负担 | 一般外观，进入分选 |
| C | moderate 缺陷负担 | 用途待评估 |
| REJECT | high 缺陷负担 | 拒收初评，暂停正常流转；记录实际处置 |

REJECT 初评不自动填写退货、隔离或处置完成。等级、建议、采用参数和实际作业仍分开记录。加工、冷链、报告及公开溯源继续关联同一来源版本。人工修正后，旧加工来源和公开快照按原规则失效并保留历史。

图片初评规则版本为 `visual-initial-v5.1`，批次初评为 `ai-batch-initial-v5.1`。YOLO 检测类别仍只有擦伤和虫害，本次没有重新训练模型或宣称准确率提高。

## 历史记录兼容

- 旧 V5 自动 D 初评按原始检测证据重新计算，追加 REJECT 的有效版本；旧记录与预测 JSON 保留。
- 旧人工图片或批次 D 不直接改写为拒收，页面提示修正为 A/B/C/REJECT，并暂停将该记录作为当前有效等级传给后续业务。
- 老检测响应的 `suggested_grade=D` 是不可变原始字段，业务使用当前 `initial_assessment`，不将旧 D 发送给 B。
- 新版接口、页面、人工修正只接受 A/B/C/REJECT。B 的算法和参数未改变，其说明文案改为“输入业务等级”，避免把 AI 输入称为人工确认。
